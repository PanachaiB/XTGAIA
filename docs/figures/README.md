# Comparison figures

Generated by `python scripts/make_comparison_figures.py` from the committed results. Colours: blue = XTGAIA,
orange = baseline run in-house on the same data, hatched aqua = value published in the comparator paper.
Suggested captions (the details removed from the plots):

- **fig0_scorecard**: like-for-like comparisons per topic (`docs/comparison_scorecard.md`). Latency is
  measured on the development laptop; the teammate's hardware run replaces it.
- **fig1a_detection_unsw**: NF-UNSW-NB15-v2, chronological 70/10/20 (CCSTGN [11] protocol); thresholds chosen
  on validation. XTGAIA = tuned final, 1 seed; [11] = mean of 5 runs; † quoted in [11] from the 3D-IDS paper.
- **fig1b_detection_cicids_heldout**: CICIDS2017 (corrected), train Mon–Thu, test Friday. No paper publishes
  this protocol, so every comparator is run in-house. Default thresholds (validation ω for the TGN).
  "Deployed" is the live pipeline model; "tuned" is the B11 result.
- **fig2_latency**: XTGAIA laptop baseline (i5-12500H, 8 GB WSL VM, no GPU, full SOC stack, 3 × 300k events)
  against AIR [5] (4 × Dell R760 + A100) at the same stage boundaries, and MTTR against Kulkarni [2].
  Execution is mostly the Shuffle webhook round trip.
- **fig3_xai**: none of the comparator papers publishes explanation latency, fidelity or stability, so all
  are measured here (1,000 instances each; XTGAIA on 1,200 detections). Fidelity: subgraph fidelity+ (XTGAIA)
  vs top-5 feature deletion. Stability: top-5 edge-set Jaccard between consecutive detections of the same
  host and class (XTGAIA) vs [6]'s cosine between nearest same-class instances. Shaded area: beyond the
  200 ms real-time bound.
- **fig4_response**: MITRE CALDERA-driven zone environment, paper reward Eq. 10. Playbooks implemented
  in-house; [2] and AIR [5] report response quality only for private deployments. No response has zero
  disruption and cost but contains only 35 % of attacks.
